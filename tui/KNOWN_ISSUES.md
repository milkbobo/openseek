# SeekMoon terminal client limitations and observed issues

## Terminal-specific limits

- The Proton embedded browser and element picker require a graphical browser surface. The TUI exposes URLs for an external browser and omits embedded browser rendering and element selection.
- PDF, Office, image, canvas, and interactive graphical previews do not render inside terminal text cells. Their original files remain attachable and accessible; source/text views and external applications provide the corresponding inspection paths.
- Window chrome, native window sizing, font-size controls, and other settings owned by the outer terminal emulator use that emulator's controls. They are not backend engine settings.
- Standalone HTML conversation export needs visualizer assets supplied to the shared server with `--viz-shell` and `--viz-bundle`. Packaged desktop builds already carry these assets; a bare server must be configured with them.

The TUI has a built-in file editor, a diff editor, a right-side file/review sidebar, and a bottom terminal sheet. PTYs, terminal input, resize, scrolling, and full-screen terminal programs are implemented; terminal editors are an additional editing option.

## Shared server lifecycle and file integrity

The following issues are implemented and covered by regressions. They are needed for existing desktop behavior to work over an independently owned server connection.

- **Final answers and history — fixed.** A completed turn can carry its final answer in a durable terminal record rather than an ordinary assistant message. The TUI renders that answer, replaces pending/queued submissions with their durable receipts, keeps live output while loading history, and reloads sequence gaps without dropping later commits. An older snapshot cannot roll history backwards. Implementation: `tui/transcript.mbt`; regressions: `tui/transcript_wbtest.mbt`. Desktop evidence: `desktop/frontend/transcript/sessions.mbt` terminal handling and `desktop/frontend/update.mbt` snapshot frontier/receipt handling.
- **Run/reply ordering — fixed.** A started/finished notification may overtake an earlier `agent.runs` reply; a queued message receipt can also overtake its direct RPC reply. The TUI captures a per-chat lifecycle generation, reconciles settled submission ids, registers queued submissions before awaiting their reply, and never restores a consumed message on a late acknowledgement. Distinct stores with the same session id retain separate state. Regressions include a real WebSocket peer forcing receipt-before-reply. Desktop evidence: `desktop/frontend/update.mbt` `SteerApplied` and run reconciliation.
- **Refused rich follow-ups — fixed.** A locally submitted steer retains its original text, image chips, file references, and attachment source roots until its exact submission id and run id settle. A refusal restores that captured input ahead of newer writing and attachments once; foreign, legacy, repeated, and wrong-run receipts do not claim the composer. A receipt can arrive before the direct RPC reply without that reply clearing the restored draft. Queued inputs retain rich snapshots when explicitly steered. Regressions: `tui/submissions_wbtest.mbt` and `tui/attachments/attachments_wbtest.mbt`. Desktop evidence: `desktop/frontend/model.mbt` `restore_submission`/`reject_steer` and `desktop/frontend/update.mbt` `SteerDropped`/`SteerRejected`.
- **Connection and listener ownership — fixed.** Client shutdown wakes pending RPC and notification consumers. A full notification queue closes the connection so reconnect can repair from authoritative snapshots. Each WebSocket owns its PTYs and watcher; teardown cancels those resources. The reusable server owns both its API and host-tool listeners, closes them on failed startup/cancellation, and supplies the same backend session MCP tool as Desktop. Regressions: `tui/client/client_wbtest.mbt`, `desktop/server/host/server_wbtest.mbt`, and `desktop/backend/remote/console_integration_wbtest.mbt`.
- **PTY races and backpressure — fixed.** Early output/exit notifications are retained until `terminal.open` attaches its screen. Output credit is acknowledged before terminal query replies can block behind a child process. Closing a tab tracks its captured PTY id across the asynchronous reply; a concurrently selected tab survives. Resize dimensions advance only after successful server acknowledgement, allowing failed resizes to retry. Explicit shutdown closes PTYs within a bounded interval, then socket teardown supplies the remaining cleanup. Regressions: `tui/terminal_wbtest.mbt` and `tui/terminal/screen_test.mbt`. Desktop evidence: `desktop/frontend/terminal/host.mbt` pending output and `desktop/frontend/terminal/update.mbt` early exit/disconnection handling.
- **Source editing and multiple clients — fixed.** File editors preserve exact tabs, CRLF endings, and UTF-8 text. CRLF is one editable newline. Saves compare the loaded disk baseline on the server, and concurrent saves are serialized, so a second stale editor cannot overwrite an already changed file. New-file saves create only absent paths. The path contract is identical to `fs.read_file`. Regressions: `vendor/tui/editor/preserve_text_test.mbt`, `desktop/backend/host/file_write_wbtest.mbt`, and `tui/workspace/workspace_wbtest.mbt`.
- **Files changed by an agent or another client — fixed.** The selected checkout installs a connection-owned, generation-tagged filesystem watcher. Events refresh explorer listings and clean file buffers, preserve folder expansion and selection, and retain dirty drafts with a visible conflict marker. A reconnect baseline repairs missed changes. Old-generation events are ignored. Unified diff previews are read-only; returning to the working view enables edits. Regressions: `tui/workspace/workspace_wbtest.mbt`.
- **Restarted server counters and offline Codex turns — fixed.** A new socket starts a new server epoch for approval, reverse-request and settings revision counters. Lower counters from a restarted host are authoritative again. Reconnect re-reads retained Codex threads and pending questions, so a turn completed offline becomes an idle, completed transcript before the next ordinary submission. Initial resync blocks submission until its snapshot settles. Regressions: `tui/connection_wbtest.mbt` and `tui/codexchat/connection_wbtest.mbt`.
- **Cross-client archive and deletion — fixed.** Identity-bearing `session.changed` events immediately remove deleted cached conversations or switch archived/live composer capability for the exact workspace and id. In-flight reads are fenced by a snapshot generation before asynchronous list refresh. This prevents an old response from restoring a deleted or writable archived selection. Regressions: `tui/connection_wbtest.mbt`. Desktop evidence: `desktop/frontend/update.mbt` `SessionsChanged` handling.
- **Selected checkout and Codex terminal identity — fixed.** New chats, project selection, Codex selection, and first-send worktree placement refresh the explorer; the previous tree disappears before asynchronous resolution, including failures. Codex PTYs use the backend's raw thread id rather than the TUI sidebar prefix, so they resolve the authorized worktree. Regressions: `tui/selection_wbtest.mbt` and `tui/terminal_wbtest.mbt`.
- **Live schedule status — fixed.** The Scheduled tasks page refreshes its snapshot on `session.changed`, so a run finishing asynchronously or in another client updates the displayed runs without reopening the page. Desktop evidence: `desktop/frontend/update.mbt` `SessionsChanged` schedule refresh.
- **Repeated server launches and exports — fixed.** Restarting the standalone server with an existing explicit runtime directory accepts that directory. Repeated HTML exports accept an existing exports directory and retain separate files for each export. Existing non-directory paths still fail through the filesystem error channel. Evidence: native server restart runtime smoke and `desktop/backend/host/session_export_wbtest.mbt`.

## Remaining observations

- In a wide diff editor, the original pane remains at its own scroll position while moving through the editable pane. The unified preview has one scroll position. A later improvement can map corresponding lines through the diff hunks and synchronize both panes without changing file contents.
- Files outside the selected checkout and files in inactive checkout tabs are saved with the same conflict checks, but the current connection's explorer watcher follows the selected checkout. Those tabs refresh when their checkout is selected; an explicit reload/revert action would improve inspection of inactive external changes.
- An explicit startup `--page` or `--session` is reapplied on reconnect. A user who navigates elsewhere after launching with either option can return to that startup selection when the connection is repaired. A later improvement should consume these options after the first successful initialization and preserve subsequent user navigation.

## Verification

Verified on Linux with the repository's native and JavaScript targets: `just check`, `just test`, and `just build` passed. The full suite passed 4,425 native tests, 4,265 JavaScript tests, 84 CLI documentation cases, and the offline CLI lifecycle/workflow integration checks. Fixture Git commits were run with signing disabled through a temporary `git` wrapper on the test process's `PATH`; no global Git configuration was changed. The first cold run of external pinned `moonx` CLI tools exceeded existing background-job test polling budgets; those tests passed with the tools cached.

A real PTY smoke session opened, edited, and saved a file; opened its Git diff; executed a command in the bottom terminal; resized the outer terminal; restarted the server with a new token and saved through the reconnected client; and quit cleanly. No live model call was needed. Listener cleanup regressions assert on the original closed handles rather than racing to rebind released ephemeral ports.
